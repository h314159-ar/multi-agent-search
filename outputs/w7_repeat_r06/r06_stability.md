## 4. 统计判读（n=8）

- 串行 5/8 vs 并行 6/8：Fisher 精确检验双侧 p = 1.0，差异不显著，8 次样本无法区分 62.5% 与 75% 的通过率。
- 单 Agent 0/8 vs 串行 5/8：p = 0.0256，单 Agent 的 0/8 是硬校验设计使然（无 Fact 声明式渲染），不是准确率略低。
- 耗时：串行 16.23±6.77s（CV 41.7%，含 31.8s 离群），并行 13.07±3.19s（CV 24.4%）；5/8 轮并行更快，逐轮耗时比中位 1.265x（离散度 ±0.805）。
- 中位数之比 = 1.094x（均值被单轮离群放大，报告优先用中位数）。
- 结论：R06 的失败集中在硬校验（派生数字、`Top-10` 带空格、以及 Planner 改走 sql 后 SQL 行号 subject 与「轻度/重度用户」引用错配），属信任层启发式边界与路由不稳定，不是并行缺陷；并行在这里只体现为耗时收益，不体现为准确率提升。
